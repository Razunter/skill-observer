## 5. Record

Call `observer_resolve` once. Send each applied on-read fix, pattern amendment or barrier rule, each withdrawal, each stale Update or Delete and each applied compaction with the `approval` of its prepared proposal: the resolver takes every rule, section, body, reference file, covered fix and deletion from that proposal's prepared `change` (for a stale answer, the `change` of the alternative the user selected), never from a fresh draft:

- `outcomes`: one entry per local, managed, upstream, plugin or new candidate: `applied`, `later` or `declined` for each answer, and `later` for each candidate past the cap and each barrier candidate set aside because the check can't run, each with its `reoffer` as Select describes. An entry for a prepared proposal cites it and carries no skill, kind, gist, fingerprint or evidence: `observer_resolve` takes them from that proposal. An applied on-read fix, pattern amendment or barrier rule cites it through `approval`, and carries no `rule`: `{ proposal: <its reference, as Prepare returned it>, selectionToolCallId: <the Select's observerToolCallId>, askToolCallId: <the ask's observerToolCallId> }`, plus `revision` when the guidance under **What to do now** in a tool result calls for it. A withdrawal the user approved is a `withdrawn` entry with `approval` the same way. Every other entry for a prepared proposal, a Later, a Decline, one Select deferred or an applied direct edit, cites it as `proposal: <its reference>`. An entry for a candidate never prepared gives its target skill, its kind (`new` for a new skill), its gist, and `evidence`: each quote it rests on, with that signal's count (1 for a signal without `(×N)` and for a User note). For a re-offered Later entry never prepared, add its fingerprint; a re-offered entry's earlier evidence carries over when its proposal or entry cites none.
