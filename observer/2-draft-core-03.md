- **Barrier rule**: first decide where the mistake shows, in your text or in one tool's call. That picks the scope: `text`, or `tool:<name>` with the tool's lowercase name, as in `tool:bash`; `tool:read` is reserved and refused, so a fix for how a skill is read is an on-read fix. Then draft the rule's name, its body, its samples and the pattern. Each sample takes the form the scope sees, as `observer_check` describes under `matches`. `matches` holds the mistake as it happened, taken from the conversation; when compaction dropped it, write a faithful reconstruction from the digest's evidence and mark it as one. `spares` holds the legitimate counterpart: the nearest correct output or call. The pattern is a regex matching the mistake as TTSR sees it, which for a tool other than `edit` and `write` is the arguments as JSON, where a quote reads `\"` and a line break `\n`. To fix a pattern amendment or barrier rule that fired on legitimate output, draft the rule again under its name for the same skill, with that output among `spares`: Prepare offers it as a rewrite that takes the fix it replaces out of force.
- **Replay**: pass every drafted pattern with its scope and samples to `observer_check` in one call. A draft is done once it passes; for each one reported misfiring, fix the pattern or a sample and check again. When the check can't run, the pass has no barrier rules: each barrier candidate goes to the ledger as `later` in step 5, unasked, with its `reoffer` as Select describes.
- **Profile guidance or settings**: read the actual file under the active OMP agent directory. Show profile-wide effect and when OMP will load it, without restarting. For a hand-written rule preserve user ownership; pass the exact proposed file as `observer_check` `ruleText`, with its basename (no `.md`), pattern, scope, actual mistake and nearest legitimate counterpart. Cite the passing call. For guidance, check a decisive inserted or removed passage. For host configuration, check the appropriate manual-only or disable change; a generic success or a check on another file proves nothing. A denied destination or unavailable necessary check is a report item with a next action, not Apply or a ledger decision.
