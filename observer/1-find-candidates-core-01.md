## 1. Find candidates

Start with the active branch, including completed work, and use the digest as an index, not a whitelist. Read the signals, corrections, observations and User note. For clipped or compacted evidence material to a finding or dismissal, retrieve the original request, reply, call or result using the active branch's saved session file, leaf and entry IDs. In a saved session, follow the leaf's parent chain, not neighboring rows from abandoned branches. If the branch lacks the source, use a narrow archive search for the named session or lead in this project, if available. Cite the decisive quote and source locator with the finding. If you cannot recover enough primary evidence, name the gap and do not present the lead as verified.

Skill findings include:

- **Improve**: the agent broke a rule a loaded skill documents; a user correction exposes a missing rule or edge case; a tool error in a turn with a skill loaded traces back to that skill's method; a better workflow emerged than the skill recommends; a skill's assumption proved wrong; new tooling made a step obsolete.
- **Simplify**: two rules contradict each other; the agent keeps failing a rule, which then becomes a barrier or goes.
- **New skill**: a multi-step workflow done by hand that no skill covers, visible as similar tool outlines across turns; a method the user explained ("I always do it this way").

**Check the current checkout before choosing a remedy.** Follow the evidence to the affected code, tests, docs or configuration; check what the existing check actually covers and whether its hook or CI wiring runs it. Repair an existing broken or unwired check rather than adding a parallel one. If production code is now correct but the old failure would still pass the suite, propose the smallest regression test in that suite, with the known bad behavior it must catch and the legitimate case it must preserve. Missing information gets a navigation or reference fix; a judgment problem gets review guidance. Treat access to information as a permission request, not authority to read a service or credentials.

**Remedy ladder.** Rank by cost, not owner: configuration or wiring repair, text or skill edit, amendment, barrier rule, pattern amendment, project check; last resorts: observer hook, then companion extension. Before proposing either, read the procedure file named below. A tool rightly rejecting misuse stays unchanged. A supplier label names a tool's supplier, not the cause; also weigh caller error, configuration, another extension's interception, unknown. Read owners' docs or source only where evidence points.

**Report items.** A finding no proposal kind fits, a capability no rung provides, or a fix in behavioural code of any extension but the companion, even under the project root, is a report item, never an edit. Give owner; request and result; expected behaviour with source or "undocumented"; cause: confirmed, suspected or unknown; a scenario proving the fix, with legitimate counterpart; next action. Missing capability: needed API, state owner, benefit, risks. Missing parts read "unknown". Not stored.
