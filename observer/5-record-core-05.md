`observer_resolve` carries out an applied on-read fix, pattern amendment or barrier rule, a withdrawal, a stale Update or Delete or an applied compaction only from the branch: the section, rule, body, reference files or deletion its prepared proposal holds, once this pass shows that proposal's successful Prepare, the Select that selected it and your `ask` whose `html` is that Select's `askHtml` unchanged, answered by the user choosing **Apply** for its `candidateId` (for a stale amendment, **Update** or **Delete**), and only while the amendment or rule file and its reference files hold the bytes Prepare read. It replays a rule's pattern before writing it and checks the approval again right after. A timeout, cancellation, nothing chosen, another option or custom input approves nothing; so does a later prompt, `/clear`, a new `/observe`, or any message the user sends after answering. Such an answer is listed as not recorded with its reason and writes nothing. Record it as Later or Decline only when the user actually answered that; otherwise select it again and ask in this pass with the new `askHtml`, or report it unrecorded. A declined or unanswered withdrawal records nothing: the fix stays in force.
