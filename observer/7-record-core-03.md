- **Profile outcomes**: use `kind: "profile"`, exact reviewed `target` and gist, and outcome. Cite `approval` for the native Apply, Later or Decline. Applied also needs `publication: { writeToolCallId, afterHash }` with the actual resulting SHA-256; Resolve checks the bytes on the reviewed target. Eligible overflow Later cites `proposal` and `reoffer` instead. A report item, unanswered question or failed write is not a profile decision.
- **Executable outcomes**: send one `kind: "harness"` entry per checked proposal, with `outcome` and the exact native `approval` for Apply, Later or Decline. For a verified Apply, add `publication: { writeToolCallIds, checkToolCallIds, files: [{ path, afterHash }] }`. Cite one successful write call per file and one successful post-write check. Use the reviewed root-relative `path` and resulting SHA-256, or `null` for removal. Resolve derives the target and evidence from the reviewed proposal and records a verified hook removal as a withdrawal. For eligible overflow, send `outcome: "later"` with its `proposal` reference and `reoffer`, not an approval. An unanswered or refused approval, refused draft, denied destination, failed write or failed check calls for a report item with the actual per-file result and next action, not a ledger decision. Do not repeat completed writes to obtain a receipt.
