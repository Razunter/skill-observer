**An approval note.** A note answers only the proposal whose option it is on. On **Apply** it approves that proposal revised by exactly the note. For an on-read fix or rule, call `observer_review` Prepare again with the same skill, kind, gist and change operation (for a rule, the same name), revised by the note, and `reconciles: { approval: <the approval, without revision>, reason: <what the note asked for>, preserved: <why the revision keeps the approved intent> }`, with `changedTarget` only when the file also changed after Prepare. Don't Select or ask again: resolve with `approval.revision` set to the revision's `reference`. When the note asks for a check or only acknowledges and the approved text stands, prepare the revision unchanged and state in `reason` what you checked. When checking shows the change should not be written, write nothing: record the proposal `later` with the note as its `reoffer` and report what you found; never `declined`. For a direct edit, make the edit as the note revises it and show its final diff in your summary. A note on a stale Update or Delete, a withdrawal or a compaction approves nothing: prepare the changed proposal and ask again. When a note on **Apply** asks for something unrelated to its proposal, record the proposal as `later` with the note as its `reoffer`, and prepare the new request as its own proposal and Ask. On **Later**, the note is that deferral's `reoffer`, in the user's words; on **Decline**, it is not recorded. Either answer keeps its option, and a request in the note for another change is prepared as its own proposal and Ask.
