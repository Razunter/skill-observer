**An approval note.** A note answers only the proposal whose option it is on. On **Apply** it approves that proposal revised by exactly the note. For an on-read fix or rule, call `observer_review` Prepare again with the same skill, kind, gist and change operation (for a rule, the same name), revised by the note, and `reconciles: { approval: <the approval, without revision>, reason: <what the note asked for>, preserved: <why the revision keeps the approved intent> }`, with `changedTarget` only when the file also changed after Prepare. Don't Select or ask again: resolve with `approval.revision` set to the revision's `reference`. For a direct edit, make the edit as the note revises it and show its final diff in your summary. A note on a stale Update or Delete, a withdrawal or a compaction approves nothing: prepare the changed proposal and ask again. On **Later**, the note is that deferral's `reoffer`, in the user's words; on **Decline**, ignore it. When a note asks for something unrelated to its proposal, record the proposal as `later` with the note as its `reoffer`, and prepare the new request as its own proposal and Ask.
