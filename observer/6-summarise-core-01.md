## 6. Summarise

Use Markdown headings and bullets in the chat summary. Put each required occurrence ID in its own bullet, not in an HTML disclosure block.

Report in a few lines: applied changes with their paths, rules and reference files included, naming each on-read fix or rule written under your reconciliation, as the result reports it; withdrawn fixes with the rule files deleted, or with the text removed from an on-read amendment as a diff; kept, updated and deleted amendments, naming each one kept without a question; Later and Decline answers; answers `observer_resolve` deferred as `later` at the replay check, and compactions it deferred as `later`, each with its reason; after a ledger failure, each Unrecorded publication, each outcome left unrecorded that wrote nothing and each answer whose recording is unknown, with the error; each deletion whose cleanup failed, with what is left; on-read fixes refused because their skill has two or more on-read amendments; barrier candidates set aside because the check can't run, with the reason it gave; dismissed signals as one line, counted and grouped by reason (e.g. `14 dismissed: 8 own tool mistakes, 4 rules that fired as meant, 2 already covered`), never listed one by one; each report item with its parts; candidates past the cap of 5; and "writing-for-agents unavailable" if step 2 fell back.

Done when the summary covers every outcome, project path and observed check result, merged finding and dismissed-signal count, deferred/failed publication, missing primary evidence or retro reference, and every other item above that occurred. Distinguish checks actually exercised from proposed checks.
