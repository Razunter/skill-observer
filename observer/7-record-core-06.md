`observer_resolve` carries out an applied on-read fix, pattern amendment or barrier rule, a withdrawal, a stale Update or Delete or an applied compaction only from the branch: the section, rule, body, reference files or deletion its prepared proposal holds, once this pass shows that proposal's successful Prepare, the Select that selected it and your `ask` whose `html` is that Select's `askHtml` unchanged, answered by the user choosing **Apply** for its `candidateId` (for a stale amendment, **Update** or **Delete**), and only while the amendment or rule file and its reference files hold the bytes Prepare read. It replays a rule's pattern before writing it and checks the approval again right after. A timeout, cancellation, missing choice, nested Ask or custom input gives no user decision. A later prompt, `/clear`, a new `/observe`, or a user message after answering invalidates the answer. Report an invalid or missing answer without a ledger decision, or ask again with the current Select form while the pass is open. A declined or unanswered withdrawal records nothing: the fix stays in force.
