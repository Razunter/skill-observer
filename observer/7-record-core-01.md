## 5. Record

A `later` the pass records itself (a barrier candidate set aside because the check can't run, a candidate deferred past the cap) carries `reoffer`: which specific observation would change the decision and when it could realistically arrive, and whether the deferred action can still be taken, checked read-only. A user's **Later** answer carries `reoffer` only from their note on that option, never your wording. The next pass sees `reoffer` under **Later** in the Proposal ledger.

**Redact new evidence before submitting Resolve.** This includes evidence supplied directly for an unprepared outcome and any older evidence you quote again. Keep real examples and non-sensitive details. Replace private values with clear placeholders such as `[redacted email]` and start an altered `quote` with `[redacted excerpt] `. Keep counts and existing `occurrenceIds`. If a value is decisive, check the primary source within scope and permissions or report the gap. Do not count a placeholder as exact recurrence. When using prepared or inherited evidence, let Resolve carry it over rather than resubmitting it. Do not rewrite earlier records or change exact approved owner-tool inputs or checks.

Call `observer_resolve` once. Send each applied on-read fix, pattern amendment or barrier rule, each withdrawal, each stale Update or Delete and each applied compaction with the `approval` of its prepared proposal: the resolver takes every rule, section, body, reference file, covered fix and deletion from that proposal's prepared `change` (for a stale answer, the `change` of the alternative the user selected), never from a fresh draft:

- `outcomes`: one entry per local, managed, upstream, plugin or new candidate with a recordable outcome. An entry for a prepared proposal cites it and takes skill, kind, gist, fingerprint and evidence from it. An applied on-read fix, pattern amendment or barrier rule cites it through `approval`, and carries no `rule`: `{ proposal: <its reference, as Prepare returned it>, selectionToolCallId: <the Select's observerToolCallId>, askToolCallId: <the ask's observerToolCallId> }`, plus `revision` when the guidance under **What to do now** calls for it. An applied direct edit cites `approval` the same way and adds `publication: { writeToolCallId: <the observerToolCallId of the edit, write or manage_skill call that made it after the Apply> }`. A withdrawal the user approved is a `withdrawn` entry with `approval`. For Later or Decline, cite `proposal: <its reference>` from the latest Prepare of the pass. Record `declined` only for the native **Decline** on that proposal's unchanged Select form. A Decline of a withdrawal records nothing: the fix stays in force. A candidate past the cap or a barrier set aside without replay goes to Later with its `reoffer`. For an unprepared barrier, give its skill, kind, gist and `evidence`: the quotes it rests on, with each signal's count (1 for a signal without `(×N)` or a User note). For a re-offered Later entry never prepared, add its fingerprint; earlier evidence carries over when the new proposal or entry cites none.
